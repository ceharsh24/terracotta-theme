Review Goals

  • Can you track active work without losing your place in dense files?

  • Do diff, shell, markdown, and logs still feel deliberate instead of second-class?

  • Selection, find match, and active line visibility
  • Added vs removed lines in review-heavy views

Findings - Dark

Daily-driver fit: Strongest all-round balance for code, config, diff, and logs. The usability pass should keep this theme feeling familiar while making active work states easier to notice.

Focus of this release: Sharper tab and panel separation, stronger find and active-line cues, and a cleaner distinction between selection-like states and structural highlights.

Findings - Dark Dimmed

Night-session fit: Still the calmest dark variant, but the surrounding surfaces now need a bit more structure so dense files do not blur together during long review sessions.

Focus of this release: Preserve comfort, restore navigation snap, and make search, bracket, and diff states more immediately visible without turning the theme harsh.

Findings - Light

Editorial fit: The warmth is part of the personality, but it needs clearer working-surface boundaries so the editor feels more intentional during config and markdown heavy workflows.

Focus of this release: Make tabs, panels, and active lines read faster while slightly reducing the amount of semantic work that depends on italic rendering.

Findings - Light Bright

Daylight fit: This variant already behaves like the most surgical light option. The usability pass should refine interaction states rather than push the palette in a new direction.

Focus of this release: Keep the cleaner surface split, strengthen navigation cues, and preserve the cooler structure lane that makes dense files easier to scan.

Findings - High Contrast CB

Accessibility fit: The editor must remain the loudest element. This pass only softens surrounding chrome where it competes with code, without weakening the accessibility-first token strategy.

Focus of this release: Keep certainty high in diff, logs, and config views while using non-code surfaces more carefully so the reading path stays centered on the editor.

Usability Summary

Primary Review Surface

This page is now the main manual usability harness for Terracotta. It combines typed code, config files, shell, markdown, diff, and logs in one theme-switchable view so a single pass surfaces real-world weak spots quickly.

What To Judge

Look for surface separation, active working-state visibility, property and operator readability in config-heavy files, and whether review-oriented panels still feel legible after long sessions.

What This Release Avoids

The family identity, semantic lane ownership, and accessibility guarantees stay intact. This is a usability refinement pass, not a brand reset or a dramatic palette overhaul.

Best Outcome

If the changes work, the themes should feel easier to navigate in motion than they do in a static screenshot, especially when moving between code, config, diff, and terminal-adjacent views.
